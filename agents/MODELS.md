# Capability Levels

- **HL:** independently reasons about cross-domain architecture, planning, requirements, evidence-backed objections and trade-offs.
- **ML:** carries out bounded implementation or mechanical work, and is the lower-priority fallback for planning when adequate.
- **LL:** mechanical transcription only, without authority over architecture or votes.

Architecture and **every council role** use **HL first, ML second**, in proposals and in every voting cycle. Use the best available adequate model in that order and record the actual model plus any fallback reason in the report. No LL council work; missing adequate HL/ML capability is PROCESS_FAILURE, not permission to drop a role or run roles sequentially.

Model/provider names are host bindings, not extra votes or tie-breakers. The role directory determines participation, not a model-specific list. Other workflow roles retain the priorities in [SHORTCUTS](SHORTCUTS.md).
