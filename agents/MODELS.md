# Capability Levels

- **HL:** independently resolves cross-domain architectural constraints and tests evidence-backed objections.
- **ML:** implements bounded contracts or performs procedural checks with explicit evidence.
- **LL:** performs mechanical transcription without technical authority.

Specialist proposal/review/consent uses HL first; ML fallback requires recorded adequate capability. Facilitator and Sealer use ML first, HL fallback. Missing adequate capability is PROCESS_FAILURE, never silent omission. LL may format decided material but cannot decide architecture, validity or consent. Actual model bindings belong to adapters; identity never supplies a vote or tie-break. See [role contracts](council/README.md).
