## VEC-01 clear classification

In `ExposedUsersRepo`, acquire the existing write lock before selecting the row and retain the raw `ResultRow` for classification. Inspect raw email, pending email, approval, and deadline because `asObject` can mask raw approval when email is null and can parse malformed raw email as null. Classify explicit null before non-null same-slot equality. An empty lifecycle means raw email null, pending null, approval false, and deadline null. Empty plus different username is username-only; truly empty with no username change is a silent no-op. Any nonempty clear checks `now < deadline` before username or lifecycle mutation, then atomically writes null current, null pending, false approval, and null deadline. Raw residual metadata therefore counts as changed and is cleared. Non-null equal-current and equal-pending requests bypass lifecycle guard, uniqueness, and clock sampling; same-current never cancels pending. Preserve missing, stale, duplicate, SQL-exception, event, and ordering contracts. Single changed events publish after commit. Bulk keeps one lock and transaction, preserves `onBeforeUpdate`, rolls back all earlier mutations on a later restricted clear, emits no event for a rejected batch, and publishes only genuinely changed rows afterward.
