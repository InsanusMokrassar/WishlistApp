## Research and limits

Kotlin's [coroutine cancellation API](https://kotlinlang.org/api/kotlinx.coroutines/kotlinx-coroutines-core/kotlinx.coroutines/-cancellation-exception/) identifies `CancellationException` as normal cancellation; the per-trigger catch rethrows it so `collectLatest` retains cancellation semantics. Kotlin's [CoroutineExceptionHandler guidance](https://kotlinlang.org/api/kotlinx.coroutines/kotlinx-coroutines-core/kotlinx.coroutines/-coroutine-exception-handler/) recommends a local `try/catch` for recoverable child work; here the local boundary is one load trigger. Playwright's [Page event API](https://playwright.dev/java/docs/api/class-page) emits `onRequest` before a response and uses `onRequestFailed` for requests with no response, so request counting belongs in that event. The correction fits the current ViewModel and strict browser collector without new infrastructure. Every behavior above has automated test coverage; no operator question is needed.
