## Research and limits

Playwright's [Java browser documentation](https://playwright.dev/java/docs/browsers) says each Playwright version needs matching binaries and Chromium headless mode has a separate shell; the design therefore probes the pinned executable and launches headless Chromium rather than trusting folder names. The [Java BrowserType API](https://playwright.dev/java/docs/api/class-browsertype) exposes `executablePath()` and `launch()`. The [Java Response API](https://playwright.dev/java/docs/api/class-response) exposes URL and status for endpoint-scoped classification. Java's [ProcessHandle API](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/lang/ProcessHandle.html) exposes descendants, per-process termination, and completion; the design adapts that API to the existing Groovy Gradle process fixture. Current public CLI `--force` guidance applies to stable branded browser channels, so this plan requires checking pinned CLI behavior before relying on it. All corrected paths are testable with local fixture/cache tests and the clean CI run; no operator decision is required before Coding.
