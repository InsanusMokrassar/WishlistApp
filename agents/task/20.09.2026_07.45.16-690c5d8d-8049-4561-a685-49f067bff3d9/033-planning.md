## Relevant findings

`features/ui/wishlist/src/commonMain/kotlin/ui/WishlistsListViewModel.kt` merges auth and resume triggers, then runs `reloadTriggers.collectLatest { loadWishlists() }` in one child coroutine. `loadWishlists()` may throw from `getMyWishlists`, `getUserWishlists`, or `getUserName`; its `finally` resets the loading flag but does not stop the exception from cancelling the collector. The method publishes rows and profile before looking up the name, so a failed `getUserName()` can leave private data visible; if the collector has died, the following logout cannot reach `clearOwnListState()`. `features/ui/wishlist/src/commonTest/kotlin/ui/WishlistsListViewModelTest.kt` uses a configurable fake for list reads but has no throwing-source recovery case. `features/ui/wishlist/README.md` documents anonymous own-list gating and public user-id browsing, and its Operator Notes contain only the template comment.

`browserTests/src/test/kotlin/dev/inmo/wishlist/browser/BrowserResponseClassifier.kt` increments `protectedOwnListRequestCount` inside `recordResponse()`, and `ServedWebSmokeTest.kt` wires only `page.onResponse`. A request failing before a response is uncounted. The collector correctly records all 401 responses, console errors, and page errors without an allowance; that strict behavior must remain. Code navigation used `ast-index outline` and `ast-index file` with the temporary index because the default cache path is read-only.

## Plan for Architecture and Coding

Place failure isolation inside each `collectLatest` trigger body, immediately around `loadWishlists()`, so a failure from one trigger does not terminate the collector that receives future auth and resume events. Catch `CancellationException` separately and rethrow it: a newer trigger must still cancel the previous load, and ViewModel disposal must still cancel the child. Log every other genuine load exception with the existing project logger, including the failure cause and enough context to identify own-list versus public-list loading. Do not silently convert a failed authenticated request into an empty successful result. Retain the existing `finally` loading reset, generation checks, and current anonymous clearing behavior. If logging itself could throw in a test logger, keep cancellation and collector survival as the primary invariant. Keep the change in the ViewModel; the protected API, model methods, and public-user path remain unchanged.

Extend `WishlistsListViewModelTest.kt` with throwing-source recovery tests driven by the real auth/resume flow: first load caller rows, make `getUserName()` throw after rows/profile publication, then emit logout and assert rows, profile, name, and loading all clear and no new protected request is made. Reauthorize or resume with a nonthrowing source and assert the same collector loads successfully. Separately make `getMyWishlists()` throw, then trigger a retry or logout/login and assert recovery. Cover a public `getUserWishlists()` failure followed by a resume retry to show anonymous public browsing still works. Where feasible, capture the test logger and assert a genuine error is logged; avoid a test that only proves the loading flag resets. Preserve the existing late noncooperative response test and add or retain a cancellation case that distinguishes expected `collectLatest` cancellation from a logged failure.

Move protected-endpoint counting to a `recordRequest` method fed by Playwright `page.onRequest`, registered before `navigate`. Match the exact same-origin `GET /api/wishlist/getMy` request, including method, path, and absence of query or user-info, using a request-detail type that does not carry HTTP status. Leave `recordResponse` responsible for rejecting 401 responses only, so a failed request without an HTTP response still increments the zero-anonymous-request counter. Update the collector test to call `recordRequest` with no matching response and expect count one; also verify unrelated path, origin, method, or query do not count. In the served anonymous smoke test assert zero actual requests after the rendered page settles, while all console/page/401 errors remain strict failures with screenshot and trace artifacts.

Run focused wishlist JVM/JS tests and browser collector tests, then the required `./gradlew build` and `./gradlew browserTest` gates. Verification should record commands, exit codes, test/browser counts, and artifacts, and confirm the served anonymous page emits zero protected request events. Previous cache repair, process cleanup, SQLite isolation, and strict console behavior remain regression conditions. After a passing local Validation, the Orchestrator should push under `agents/GIT.md` and inspect a fresh clean-checkout CI run of the same `./gradlew browserTest` command; until that run is observed, clean-runner provisioning remains unverified.
