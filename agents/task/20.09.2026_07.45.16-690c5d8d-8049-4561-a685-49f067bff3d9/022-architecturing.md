## Design

Fix the source of the anonymous error in `features/ui/wishlist/src/commonMain/kotlin/ui/WishlistsListViewModel.kt`. For `WishlistsListViewConfig(userId = null)`, treat `model.userAuthorisedState` as the gate for the protected `getMyWishlists()` call. The existing `WishlistsModel` already exposes that `StateFlow`; no model, server, or HTTP API contract change is needed. On false, do not call the endpoint, set `wishlistsState` to empty, `profileUserIdState` and `userNameState` to null, and `loadingState` to false. On true, load the caller's list and identity as before. For `userId != null`, keep `getUserWishlists(userId)` public and independent of auth state, keep the profile target as that user, and resolve that user's name. Existing `isOwnerState` remains reactive through `isOwnerFlow`.

Make loading react to the auth state as well as resume. A narrow implementation is an own-list trigger flow combining `model.userAuthorisedState.map { Unit }` (the `StateFlow` initial emission supplies initial load) and `node.onResumeFlow`; public-list mode uses `flowOf(Unit)` plus resume only. Collect each merged flow with `collectLatest` in the ViewModel scope so login starts a new load and logout cancels the old load before clearing state. Keep the existing logging behavior for genuine authenticated failures: do not catch or turn a failed `getMyWishlists()` into an empty list. Avoid a second unconditional initial trigger for own-list mode, which would duplicate startup requests. Use a monotonically increasing load generation if needed across explicitly launched load jobs and check both current generation and `model.userAuthorisedState.value` before publishing caller-derived rows, profile, or name. Cancellation alone is insufficient if a fake/noncooperative source returns after cancellation; the publication guard is the final privacy invariant. Check authorization again after `getUserName` before publishing its result. In `finally`, only the current load may reset `loadingState`, preventing an old canceled request from making a newer load appear finished. Logout should clear caller-derived state before any further suspend point. Public-list results must not be erased just because the viewer logs out.

## Test specifications

`WishlistsListViewModel` own-list startup: with `userId=null` and auth=false, advance test dispatcher; expect zero `getMyWishlists()` calls, empty `wishlistsState`, null profile/name, and `loadingState=false`. Emitting resume while still false must retain those results and issue no protected request. With auth=true at startup or after login, expect one protected read per effective trigger, loaded rows, caller profile ID/name, and loading reset. With auth=true then false, expect rows/profile/name cleared immediately and no new protected read; resume after logout must remain empty. With false→true again for another caller, expect a fresh load and no prior caller rows. If authenticated `getMyWishlists()` throws (including 401/decode failure), expect the error to remain visible to the existing logging path rather than a silently successful empty result, and loading resets.

`WishlistsListViewModel` public-list mode: with `userId=<other>` and auth=false, expect one `getUserWishlists(<other>)` call, visible rows, target profile ID/name, and no `getMyWishlists()` call. Login/logout changes must not clear public rows; resume reloads the same public target. Ownership state may change reactively but does not change the public fetch gate.

`WishlistsListViewModel` stale-load case: hold a successful caller-list response at a controllable suspend point, emit logout, then release the old response (including a source that ignores cancellation); expect no caller rows, profile, or name published, and loading false. Also hold name resolution across logout and ensure no stale name appears. For quick logout→login, a previous caller's response must not overwrite the new caller's data; only the latest generation may publish or clear the latest loading state.

`BrowserErrorCollector` classifier tests: an anonymous unlocated or `webpack-internal://` transformation error fails even after recording an exact former bootstrap 401; an authenticated transformation error fails; an anonymous `/api/wishlist/getMy` 401 fails once the obsolete allowance is removed; any other API 401 and any page error fail. Delete tests that assert acceptance of the old transformation/401 allowance. The served smoke test must observe zero anonymous protected-list requests and zero console/page errors on both paths; an injected unexpected authenticated 401 remains a negative test and must retain screenshot/trace. These checks prove the source fix and the strict browser gate together.

## Research and limits

Kotlin's [collectLatest documentation](https://kotlinlang.org/api/kotlinx.coroutines/kotlinx-coroutines-core/kotlinx.coroutines.flow/collect-latest.html) confirms that a new auth emission cancels the previous load action; the design adapts that behavior to the existing ViewModel scope and adds a publication guard for noncooperative work. [StateFlow documentation](https://kotlinlang.org/api/kotlinx.coroutines/kotlinx-coroutines-core/kotlinx.coroutines.flow/-state-flow/) confirms an initial current value and equality-conflated auth changes, supporting one initial own-list trigger without a duplicate `flowOf(Unit)`. The repository's own API contract marks `getMyWishlists()` protected and `getUserWishlists(userId)` public; the fix belongs in the list ViewModel rather than changing server authorization. All planned behavior has automated ViewModel and browser coverage; no operator decision is required before Coding.
