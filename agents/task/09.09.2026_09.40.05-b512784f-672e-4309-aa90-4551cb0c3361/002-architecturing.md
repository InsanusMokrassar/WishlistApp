## Research and adaptation

The [OWASP password recovery guidance](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html), consulted on 9 September 2026, supports unpredictable expiring single-use authorization, confirmation fields, trusted-origin URLs, referrer protection, and ordinary login after completion. Here the request already has an authenticated subject, so anonymous account-discovery and uniform response timing are outside the requested flow. Keep a 15-minute lifetime and the existing UUID generator. Existing-session revocation and a second notification email are not accepted additions: the chosen product scope preserves sessions and requires one request email. No queue or new rate-limit framework is needed for this change.

The [OWASP password storage guidance](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html) identifies BCrypt's 72-byte limit. The new operation therefore requires at least eight Kotlin string characters and at most 72 UTF-8 bytes, with no trimming, normalization, composition rules, or silent truncation. Retain the existing BCrypt implementation and salt generation; migrating algorithms or changing legacy registration and admin policy would expand scope.

The [JDK 17 MessageDigest contract](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/security/MessageDigest.html) supplies SHA-256 and digest comparison. Use that primitive for a server-private credential-state fingerprint, not for password storage. The invalidation property is a design inference: every existing password replacement generates a fresh BCrypt salt and changes the stored hash, so a digest of that record changes even when the same plaintext password is set again.

The [Kotlin cancellation documentation](https://kotlinlang.org/api/kotlinx.coroutines/kotlinx-coroutines-core/kotlinx.coroutines/-non-cancellable/) and [ensureActive contract](https://kotlinlang.org/api/kotlinx.coroutines/kotlinx-coroutines-core/kotlinx.coroutines/ensure-active.html) support explicit active checks around a small non-cancellable commit or cleanup. Do not run SMTP or acquire the outer account lock in a non-cancellable region. Do not launch detached non-cancellable jobs. Repository operations must eventually return; these mechanisms do not provide crash recovery or a distributed transaction.

The [Ktor AuthCircuitBreaker contract](https://api.ktor.io/ktor-client-auth/io.ktor.client.plugins.auth/-auth-circuit-breaker.html) explicitly skips authentication and refresh for a request. Use the request attribute on completion so an unrelated browser session cannot be refreshed, cleared, or replaced by a failed completion response. The [Ktor logging formatter](https://ktor.io/docs/server-call-logging.html?topic=.2.0) permits safe method/status logging without a URI. The [Referrer-Policy documentation](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Referrer-Policy) supplies the actual `no-referrer` policy value; install it before the HTML shell loads external fonts or scripts.
