## Current primary-source research

Research was performed during this invocation on 5 October 2026 using the native web tool. Sources were consulted directly rather than inherited as fresh research from the completed design.

[RFC 9110 section 9.2.2](https://www.rfc-editor.org/rfc/rfc9110.html#section-9.2.2) restricts automatic retry of non-idempotent requests when application cannot establish that the first request was unapplied. Adaptation: retain the page-local terminal uncertainty guard for the completion POST and a truthful exit. A later InvalidApproval cannot prove a lost response meant failure. A durable receipt endpoint would be a broader product/protocol change and is excluded.

[OWASP Forgot Password Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html) supports expiration and one-use tokens. Adaptation: retain existing expiry, subject/email/fingerprint guards and persistent consumption. Session revocation, new notification delivery, recovery redesign and policy changes are outside the reviewed repair; the explicit retained-session requirement governs this task.

[PostgreSQL transaction isolation](https://www.postgresql.org/docs/current/transaction-iso.html) explains conflicting DELETE behavior and predicate reevaluation at Read Committed; [DELETE](https://www.postgresql.org/docs/current/sql-delete.html) describes affected-row results. Adaptation: authorization requires one committed DELETE matching exact observed content. Real independent-connection tests are essential; a shared process mutex or SQLite-only test cannot establish the PostgreSQL guarantee. Stronger isolation may fail conservatively; failure cannot authorize a write.

[Exposed CRUD](https://www.jetbrains.com/help/exposed/dsl-crud-operations.html) and [transactions](https://www.jetbrains.com/help/exposed/transactions.html) document deletion and transaction boundaries. Adaptation: retain existing Exposed and return after the short top-level transaction in the current production call path, preserving the separate password commit. An enclosing application transaction must not be introduced around authorization because a nested transaction can share the outer commit. This is an integration invariant, not a discovered failure in the inspected caller path or a requirement for a dependency upgrade.

[PostgreSQL LIMIT/OFFSET](https://www.postgresql.org/docs/current/queries-limit.html) requires predictable ordering for bounded selection. Adaptation: database-ordered full key/value cursors and a captured inclusive upper bound avoid deletion-induced OFFSET skips and keep each sweep finite. Full-table metadata migration could improve future scale but is unnecessary for the scoped correction.

[Kotlin coroutine exception handling](https://kotlinlang.org/docs/exception-handling.html) and [NonCancellable](https://kotlinlang.org/api/kotlinx.coroutines/kotlinx-coroutines-core/kotlinx.coroutines/-non-cancellable/) describe cancellation propagation and warn against severing lifecycle ownership with NonCancellable coroutine builders. Adaptation: keep the cleaner a child of the server scope and rethrow cancellation; retain bounded existing withContext(NonCancellable) commit work. No detached maintenance coroutine is selected.

## Alternatives, compatibility, rollout and risks

The recommended architecture retains additive storage capability and the present raw compare-and-delete. Read plus unconditional Unit-returning unset and process-local locks fail the shared-store winner requirement. A single-process restriction is a credible alternative but depends on deployment policy and would leave the narrow storage weakness; no topology choice is needed with the current remedy. Combining consume/password write in one transaction would reverse the deliberate burn-before-write choice and is rejected under AC6. New receipt endpoints, durable unknown-result navigation, session revocation and distributed account locking exceed scope.

Open-triggered or issuance-only cleanup cannot reach idle never-opened approvals. getAll has unbounded memory cost and OFFSET can skip records after deletion. Indexed purpose/expiry metadata could improve scale but introduces schema/backfill work beyond this repair; finite ordered pages handle existing data without a migration. The cleanup contract bounds memory and page work, not wall-clock retention through outage or unbounded table growth. Rows inserted behind an active cursor are reached after a later reset.

Rollout must follow existing feature instructions: preserve backup/recovery checks, validate existing raw timestamp counts before deployment, stop old writers, deploy matching server/UI and invalidate old assets.
