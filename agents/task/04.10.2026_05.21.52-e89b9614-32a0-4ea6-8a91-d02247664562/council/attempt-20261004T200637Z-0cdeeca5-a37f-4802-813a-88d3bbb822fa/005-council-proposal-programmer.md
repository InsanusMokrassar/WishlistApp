## External feasibility research

PostgreSQL documents that Read Committed DELETE waits for conflicting writers and ignores a row already deleted by a committed contender; its search predicate is checked against the updated version. The inspected id/raw predicate is a direct fit for that behavior. This is an inference about this implementation, supported by the independent-connection regression specifications. [PostgreSQL 18 transaction isolation](https://www.postgresql.org/docs/18/transaction-iso.html).

DELETE's affected-row count distinguishes a successful deletion from a zero-row result, while Exposed's transaction API places execution inside a database transaction. A one-row statement result must therefore remain provisional until transaction completion; the inspected source returns after that boundary and the deferred-trigger test checks failure there.
