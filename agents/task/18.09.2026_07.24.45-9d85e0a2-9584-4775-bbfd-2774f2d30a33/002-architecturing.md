## Chosen contract and ownership

Introduce the concrete serializable data class EmailProfile in features/email/common/src/commonMain/kotlin/models/EmailProfile.kt, package dev.inmo.wishlist.features.email.common.models. Its exact properties are userId: Long with no default, email: Email? = null, emailApproved: Boolean = false, pendingEmail: Email? = null, emailChangeRequestedAt: Long? = null, and emailChangeAllowedAt: Long? = null. Neither this class nor any alias implements User, wraps RegisteredUser/AuthFeatureUser/AdminUser, carries username, or nests a user model.

Choose the flat profile over a nested PendingEmailChange DTO. The first unapproved address is in email, while a replacement after approval is in pendingEmail. A single requested-at value describes the active verification candidate in either location. A nested replacement-only object would omit initial-request time or require another representation. Current email and approval belong in this email response because the editor and delivery service need one coherent row snapshot to distinguish first verification, approved current, pending replacement, and promotion. These two existing identity fields also remain on private user/auth/admin models.

The owner identifier is Long because users/common already depends on email/common; importing UserId into the email/common DTO creates a cycle. Map UserId using its long property and compare response.userId with the expected UserId.long at UI boundaries. Do not relocate UserId, add an identifier framework, or change module dependencies.

Both time properties are nullable UTC epoch milliseconds. emailChangeRequestedAt records the server time of the accepted durable write introducing the active verification candidate, including initial unapproved creation. It is not delivery time or a restriction deadline. Null means no outstanding request in a normal empty/approved state, or unknown historical time for a legacy candidate. No read/migration fabricates a timestamp. emailChangeAllowedAt remains rooted at successful approval. Requested-at is not a unique generation token and adds no compare-and-swap, link expiry, resend restriction, or same-address generation protocol.

Use the existing application Json with ignoreUnknownKeys=true and default encodeDefaults=false. Optional DTO defaults accept absent metadata; userId is required. Populated fields serialize normally. An existing empty account can serialize with only userId. JSON null, absent body, invalid Email, missing userId, and wrong scalar types are not successful profiles. No @Transient properties, deprecated aliases, pending extension properties, or nested EmailProfile compatibility substitutes may remain on user models.

## Lifecycle transitions

Every participating writer acquires users_write_lock before checking raw cross-slot ownership and changing data. A state-changing replacement/clear is allowed only when the persisted deadline is absent or server time is at least that deadline.

| Before and operation | Current/approval/pending after commit | Requested-at after commit | Deadline and event |
|---|---|---|---|
| Create without email | null / false / null | null | Null deadline; existing create event. |
| Create with A or set A on empty account | A / false / null | Accepted write's post-lock time. | Null deadline; one create/update event. |
| Unapproved A replaced by B | B / false / null | B's accepted-write time. | Clear admitted residual deadline; one update event. |
| Approved A accepts replacement B | A / true / B | B's accepted-write time. | Retain existing approval-rooted deadline; one update event. |
| Approved A with pending B accepts C | A / true / C | C's accepted-write time. | Retain deadline, release B ownership; one update event. |
| Save exact current or exact pending, including A while B is pending | Unchanged; saving A does not cancel B. | Unchanged, including legacy null. | Unchanged; no email event unless full update actually renames user. |
| Username-only write | All email columns unchanged. | Unchanged. | Unchanged; only real rename emits update. |
| Approve exact first unapproved A | A / true / null | null | Deadline from approval time; one update event. |
| Approve exact pending B | B / true / null | null | Deadline from approval time; one update event. |
| Replay exact approved current without pending | Unchanged. | Unchanged. | No deadline extension/event. |
| Stale, cleared, missing, superseded, or legacy-null approval | Unchanged. | Unchanged. | No lifecycle event/role promotion. |
| Clear non-empty raw lifecycle, including request-only residue | null / false / null | null | Null deadline after admitted clear; one event. |
| Clear completely empty raw lifecycle | Unchanged. | null | No event. |
| Read, resend, successful/failed SMTP, blocked/failed mutation | Unchanged. | Unchanged. | No lifecycle event. |
| Delete | Remove users row. | Removed with row. | Existing deletion event/cascade. |

Migrated unapproved/pending candidates remain usable with unknown requested-at. Same-address saves and resends do not invent time; only a different accepted candidate stamps it. Clock values may repeat within one millisecond because metadata is not a generation token.
