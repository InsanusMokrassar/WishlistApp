## Implemented behavior

`RegisteredUser.emailApproved` is a defaulted, persisted, private field. The Exposed table adds `email_approved` with a false default. Inserts begin false, matching-email updates preserve approval, and changed or cleared addresses reset it. `approveEmail(id, expectedEmail)` performs the id-and-current-email conditional update, emits the updated record after commit, and CacheUsersRepo mirrors only successful results without holding its lock across the backing repository call. Public `UsersFeatureUser` continues to expose neither private email field, and its reverse mapper now requires both omitted values explicitly.

The authenticated own-record and root-only admin models carry the defaulted approval state. The email feature adds an authenticated request endpoint with explicit Sent, AlreadyApproved, Unavailable, NoEmail, EmailChanged, and DeliveryFailed outcomes. It sends only to the caller's exact current pending address, rechecks after delivery, and removes only its request-local deeplink when the address becomes stale. SMTP-disabled storage remains available while verification requests return Unavailable.

The existing verification handler now conditionally persists approval before attempting promotion. Role promotion grants User only from a direct NewUser marker; a user whose access was removed does not regain User through a later verification link. Full admin updates now share the account coordinator, and a new root-authorized username-only route preserves the current email and approval state. Both the administrator editor and the root profile editor use that route for existing-user renames.

The owner profile editor fetches the authenticated private profile only for the edited owner when email verification is enabled. It supports adding a missing email, saving before requesting verification, retrying a pending address without rewriting it, refresh, explicit errors and delivery outcomes, and a read-only approved state. The same controls exist in JVM, JS, and Android views; users cannot see another account's private email controls. The admin dashboard now loads actual users with loading, empty, retryable error, and row-navigation behavior. Its SMTP form is capability-aware and clearly says that the recipient receives a test only and that no account email is changed.
